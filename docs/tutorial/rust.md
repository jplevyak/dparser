# 9. Rust

DParser has a native Rust runtime, a port of the C one. You write the
grammar in the same `.g` syntax with Rust code in the actions, and
`make_dparser` turns it into tables that your program embeds. Nothing is
written in C.

This chapter builds a calculator in Rust, then adds variables and blocks
with the symbol table, as in [Scopes and State](scopes-and-state.md), and
finally loops with threaded state.

## Setting up the crate

```bash
cargo new calc
```

`Cargo.toml`:

```toml
[package]
name = "calc"
version = "0.1.0"
edition = "2024"

[dependencies]
dparser = { git = "https://github.com/jplevyak/dparser" }

[build-dependencies]
dparser = { git = "https://github.com/jplevyak/dparser" }
```

The grammar is compiled when the crate is built. `build.rs` runs
`make_dparser`, which the `dparser` crate builds and makes available to
your build script, and then `dparser::build_actions`, which turns the
actions into Rust:

```rust
use std::env;
use std::path::PathBuf;
use std::process::Command;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    println!("cargo:rerun-if-changed=src/calc.g");

    let out_dir = PathBuf::from(env::var("OUT_DIR")?);
    let grammar = PathBuf::from(env::var("CARGO_MANIFEST_DIR")?).join("src/calc.g");
    let tables = out_dir.join("calc.g.d_parser.bin");
    let actions = out_dir.join("calc.actions");

    // make_dparser, built by the dparser crate, writes the tables and the actions
    let make_dparser = PathBuf::from(env::var("DEP_DPARSE_BINARY_PATH")?);
    let status = Command::new(make_dparser)
        .arg(&grammar)
        .args(["-B", "-X", "bin", "-o"]).arg(&tables)
        .arg("-a").arg(&actions)
        .status()?;
    if !status.success() {
        return Err("make_dparser failed".into());
    }

    // turn the actions into Rust: GlobalsStruct and NodeStruct are defined in calc.g
    dparser::build_actions(&actions, &out_dir.join("actions.rs"), "GlobalsStruct", "NodeStruct")?;
    Ok(())
}
```

## A calculator

`src/calc.g`:

```rust
{
#[derive(Debug, Default)]
pub struct GlobalsStruct {
    pub output: Vec<String>,
}

#[derive(Debug, Default, Clone)]
pub struct NodeStruct {
    pub value: i64,
}
}

program: statement* ;

statement: expr ';' { $g.output.push($0.value.to_string()); } ;

expr: expr '+' expr $left 10  { $$.value = $0.value + $2.value; }
    | expr '*' expr $left 20  { $$.value = $0.value * $2.value; }
    | '(' expr ')'            { $$.value = $1.value; }
    | number                  { $$.value = $0.value; }
    ;

number: "[0-9]+" { $$.value = $n0.string.parse().unwrap(); } ;
```

This is the C calculator with Rust actions:

- **The global code** at the top, in `{ }`, is Rust. It defines the two
  types named in `build.rs`: `GlobalsStruct`, the parse's globals (`$g`),
  and `NodeStruct`, each node's data (`$$`, `$0`, `$1`, ...).
- **`$n0`** is element 0 itself, and `$n0.string` its text.
- **`$g`** is `&mut GlobalsStruct` in final actions. Here they collect
  the output.

`src/main.rs`:

```rust
use dparser::Parser;

include!(concat!(env!("OUT_DIR"), "/actions.rs"));

const TABLES: &[u8] = include_bytes!(concat!(env!("OUT_DIR"), "/calc.g.d_parser.bin"));

fn main() {
    let input = std::env::args().nth(1).unwrap_or_default();
    let mut parser: Parser<GlobalsStruct, NodeStruct> = Parser::new(TABLES, Some(dispatch_action)).unwrap();
    parser.set_loc("input", 1);
    let mut globals = GlobalsStruct::default();
    match parser.parse(&input, Some(&mut globals)) {
        Some(_) if parser.syntax_errors == 0 => {
            for line in &globals.output {
                println!("{}", line);
            }
        }
        _ => std::process::exit(1),
    }
}
```

`actions.rs`, generated by `build.rs`, defines the types from the global
code and `dispatch_action`, which runs the actions. The tables are
embedded with `include_bytes!`.

```console
$ cargo run -q -- '1 + 2 * 3; (1 + 2) * 3;'
7
9
$ cargo run -q -- '1 + ;'
input:1: syntax error after '+'
```

## Variables and blocks

Now the language of [chapter 6](scopes-and-state.md): declarations,
assignments and blocks. Replace `src/calc.g` with:

```rust
{
#[derive(Debug, Default)]
pub struct GlobalsStruct {
    pub output: Vec<String>,
}

#[derive(Debug, Default, Clone)]
pub struct NodeStruct {
    pub value: i64,
}
}

program: statement* ;

statement
  : name ':' expr ';'
      [ let s = ${parser}.symtab.speculative_new_sym(&mut ${scope}, $n0.string);
        ${parser}.symtab.sym_mut(s).user = $2.value as u64; ]
  | name '=' expr ';'
      [ let Some(s) = ${parser}.symtab.find_sym(${scope}, $n0.string) else { ${reject}; };
        let s = ${parser}.symtab.update_sym(s, &mut ${scope});
        ${parser}.symtab.sym_mut(s).user = $2.value as u64; ]
  | expr ';'
      { $g.output.push($0.value.to_string()); }
  | '{' new_scope statement* '}'
      [ ${scope} = ${parser}.symtab.enter_scope(${scope}, $n0.scope); ]
  ;

new_scope: [ ${scope} = ${parser}.symtab.new_scope(Some(${scope})); ] ;

expr: expr '+' expr $left 10  [ $$.value = $0.value + $2.value; ]
    | expr '*' expr $left 20  [ $$.value = $0.value * $2.value; ]
    | '(' expr ')'            [ $$.value = $1.value; ]
    | number                  [ $$.value = $n0.string.parse().unwrap(); ]
    | name
        [ match ${parser}.symtab.find_sym(${scope}, $n0.string) {
            Some(s) => $$.value = ${parser}.symtab.sym(s).user as i64,
            None => ${reject},
          } ]
    ;

number: "[0-9]+" ;
name: "[a-z]+" $term -1 ;
```

What changed:

- **The expression actions are speculative**, `[ ]`, because a
  declaration has to store its value in the symbol table during the
  parse, before final actions run. Values in `$$` stay with the nodes, so
  the statement's final action still prints them.
- **`${parser}.symtab`** is the symbol table, a port of the C one.
  Scopes and symbols are `ScopeId`s and `SymId`s, and each symbol has a
  `u64` of your data, `user`.
- `speculative_new_sym(&mut ${scope}, name)` declares a symbol on this
  parse path only, and `update_sym(s, &mut ${scope})` makes a new
  version of one to change, as `SPECULATIVE_NEW_D_SYM` and `UPDATE_D_SYM`
  do in C. `new_scope` and `enter_scope` open and close blocks.
- **`${reject}`** rejects the parse path, here for a name that isn't
  declared.

```console
$ cargo run -q -- 'x: 1;
y: 2;
{
  x: 10;      // a new x, only in this block
  x + y;
  y = x + y;  // changes the outer y
}
x;
y * 2;'
12
1
24
$ cargo run -q -- 'x: 1; { z: 2; } z;'
input:1: syntax error after 'z'
```

## Loops

Last, `while` loops and `break`, which is legal only inside a loop. As in
[chapter 6](scopes-and-state.md#context-that-isnt-a-name), the loop depth
is threaded state, `${state}`, which flows along each parse path.

In Rust, a state is a `StateId`, a handle to a value interned by the
parser: `${parser}.make_state(value)` gives the id of any value that
implements `Eq` and `Hash`, and `${parser}.state::<T>(id)` gets it back.
`StateId::NONE` means no state.

Add two helper functions at the end of the global code:

```rust
type P = dparser::Parser<GlobalsStruct, NodeStruct>;

/// The loop depth in a threaded state: no state is depth 0.
fn depth(p: &P, s: dparser::StateId) -> i32 {
    p.state::<i32>(s).copied().unwrap_or(0)
```

and two rules for `statement`, with `enter` and `leave`:

```rust
statement
  : ...
  | 'while' '(' expr ')' enter statement leave
  | 'break' ';'
      [ if depth(${parser}, ${state}) == 0 { ${reject}; } ]
      { $g.output.push(format!("break at loop depth {}", depth(${parser}, ${state}))); }
  ;

enter: [ let d = depth(${parser}, ${state}); ${state} = with_depth(${parser}, d + 1); ] ;
leave: [ let d = depth(${parser}, ${state}); ${state} = with_depth(${parser}, d - 1); ] ;
```

```console
$ cargo run -q -- 'x: 1;
while (x) { x + 1; break; }
while (x) while (x) break;
while (x) { while (x) x; break; }'
2
break at loop depth 1
break at loop depth 2
1
break at loop depth 1
$ cargo run -q -- 'x: 1; break;'
input:1: syntax error after ';'
```

This parser doesn't run the loops: it checks where `break` may appear.
`with_depth` returns `StateId::NONE` for depth 0 so that leaving the last
loop gives the same state as never entering one; equal states let the
parser share work between paths.

## Differences from C

- `$g` is `&GlobalsStruct` in speculative actions, so they can't change
  it. Keep path-specific data in `$$`, the symbol table or `${state}`.
- Action code is Rust, so `$$ = $0.clone()` copies a node's data, and a
  speculative action rejects with `${reject}` (which is `return -1`).
- With [`AttrTree`](../reference/attributes.md#rust-dparserattrs) you can
  compute [attributes](attributes.md) on the tree that `parse` returns.

The [Rust reference](../reference/rust.md) has every specifier and parser
option.

## What you learned

- `build.rs` runs `make_dparser` and `build_actions`; your program embeds
  the tables and includes the generated `actions.rs`.
- Actions are Rust, with the same specifiers as C.
- `${parser}.symtab` and `${state}` work as in C, with `ScopeId`, `SymId`
  and `StateId` handles.

covers everything in full detail.
